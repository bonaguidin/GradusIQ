## Running Playwright in the Claude Code sandbox

This sandbox CAN launch a real browser for Playwright; it just needs the right binary named explicitly. (Moved from `planning-docs/outstanding-fixes.md`, where it was a correction to an old CI-gate tracking item that has since been condensed. Wording below is unchanged except for references to sections that no longer exist, now pointed at `docs/url-state-guide.md`.)

Every earlier round of that tracking item said "this sandbox can't launch the pinned browser build" and settled for reading source instead of running tests. That premise was wrong, or at least incomplete: `/opt/pw-browsers/chromium` (a plain, non-headless-shell Chromium build, version 1194) runs fine; `chromium.launch()`'s *default* choice (`chromium_headless_shell-1228`, not present here) is what was missing, not every browser. Passing `executablePath: '/opt/pw-browsers/chromium'` to `chromium.launch()` is sufficient. Confirmed by actually running `authenticatedDashboard.test.mjs`, `termSelectorDefault.test.mjs`, `degreeScheduleYears.test.mjs`, `degreeScheduleYearsAdd.test.mjs`, `careerOptimizationOptIn.test.mjs`, and the full 511-test suite (three runs across the URL-state work described in `docs/url-state-guide.md`: two came back at 509-510/511 with a different single failure each time, both real -- a non-exact `getByRole('button', {name:'Career'})` locator in `resumeRecovery.test.mjs` that only `page.reload()` now makes ambiguous (fixed with `exact: true`) and one apparently load-sensitive timeout in `transcriptFlow.test.mjs` that passed cleanly on its own when re-run in isolation twice; the third run, after the real fix, came back clean at **511/511**) in this same sandbox during that URL-state work. Also needed: a local-only `frontend/.env` with the two public (non-secret) `VITE_SUPABASE_*` values from `.env.example` -- without it the dev server throws before any component mounts. Neither change belongs in the repo (the executablePath is a sandbox-only shim applied via `--import` preload and reverted before committing; `.env` is already gitignored) -- noted here so a future round doesn't re-discover this from scratch and settle for reasoning-only verification again.
